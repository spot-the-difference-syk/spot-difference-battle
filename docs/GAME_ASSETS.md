# 게임 문제 에셋 가이드

> 문서 상태: CURRENT
> 기준일: 2026-10-01

## 1. 에셋 모델

게임 콘텐츠 단위는 단일 장면이 아니라 `원본 + 변경본 + 정답 3곳`으로 구성된 문제 쌍이다. 경기 중 플레이어가 이미지를 수정하지 않는다.

새 그림은 코드 수정·재배포 없이 **R2(이미지) + Supabase `puzzle_catalog`(정답·노출 여부)** 로 추가한다. 절차는 아래 "7. 새 그림 등록"을 따른다. 앱 번들에 들어 있는 기존 15점(대결 10, 솔로 5)은 서버나 DB에 닿지 못할 때 쓰는 기본 목록이다.

번들 그림의 기준은 `packages/shared/src/puzzles/asset-manifest.ts` 한 곳이다. 이 매니페스트가 문제 ID, 버전, 난이도 상태, 권리 상태, 원본·변경본 파일명, 크기와 SHA-256을 공유하며 웹·서버 테스트가 실제 파일 및 카탈로그와의 일치를 검사한다. 배포 이미지는 `apps/web/src/assets/puzzles/`에만 두며, 이미지 파일을 교체할 때는 같은 이름으로 덮어쓰지 말고 버전과 해시를 함께 올려야 한다.

현재 5세트의 난이도는 플레이 데이터가 없어 `UNRATED`, 권리 상태는 사용자가 직접 제작·제공했음을 뜻하는 `USER_SUPPLIED`로 기록한다. `USER_SUPPLIED`는 제공 경로 기록이지 제3자 법률 검증을 뜻하지 않는다.

문제마다 다음을 준비한다.

- 고유 `pairId`와 버전
- 원본 PNG와 서비스용 WebP 또는 AVIF
- 변경본 PNG와 서비스용 WebP 또는 AVIF
- 정확히 3개의 정답 ID·이름·정규화 영역
- 이미지 크기·해시와 난이도
- 원작자, 생성 도구, 생성일, 이용 조건과 원본 증빙
- 모바일 육안 검수 결과와 활성 상태

## 2. 현재 보유 상태

| 장면 | 원본 | 변경본 | 문제 사용 상태 |
|---|---|---|---|
| 햇살 좋은 카페 | 있음 | 있음 | 활성: 시계·꽃·고양이 3곳 등록 |
| 마법의 버섯 숲 | 있음 | 있음 | 활성: 등불·목도리·지붕 새 3곳 등록 |
| 바닷속 보물 | 있음 | 있음 | 활성: 거북이 모자·해파리·보물상자 3곳 등록 |
| 네온 사이버 도시 | 있음 | 있음 | 활성: 네온·비행 자동차·헤드폰 3곳 등록 |
| 눈 내린 겨울 산장 | 있음 | 있음 | 활성: 연기·눈사람 모자·모닥불 3곳 등록 |
| 카툰 연구실 | 있음 | 없음 | 변경본 필요 |
| 따뜻한 거실 | 있음 | 없음 | 라이선스 미확인, 출시 제외 |

이전 카페·도시 동일 파일과 추가 차이가 있던 숲 파일은 역사 자산으로만 보존한다. 2026-08-09에 제공된 새 5쌍은 각 쌍의 의도한 차이 3곳을 수동 정답 영역으로 등록했다. 제공 JPG의 SHA-256은 권리 기록에 보존하고, 웹 배포에는 동일한 1024×1024 크기의 WebP 품질 88 파생본을 사용한다.

현재 온라인 테스트에는 카페·숲·바다·도시·겨울 5세트가 등록돼 있다. 내부 기능 검증 수량은 충족했지만 실제 사용자 플레이를 통한 경계·난이도 조정과 3분 경기용 10세트 확보는 남아 있다.

10개 배포 이미지의 합계는 JPG 10,032,236바이트에서 WebP 2,654,722바이트로 줄었다. 변환 PSNR은 37.36~39.82dB이며 모든 파일의 1024×1024 RGB 디코딩을 확인했다.

## 3. 이미지 조건

- 원본과 변경본의 크기·비율·구도·크롭이 같음
- 제목, A/B 표시, 테두리, 상표와 워터마크 없음
- 의도한 차이는 정확히 3곳
- 영역 밖 화풍·조명·노이즈 변화 최소화
- 모바일에서 확대했을 때 독립적으로 식별 가능한 크기
- 색상만 구별해야 하는 문제에 의존하지 않음
- 정답 영역이 겹치지 않고 화면 가장자리에서 잘리지 않음

첫 출시 문제는 원본과 변경본 모두 같은 1024×1024 정사각형이어야 한다. 비정사각 이미지는 실제 `object-fit` 표시 영역에 맞춘 좌표 변환을 구현하고 자동 검증하기 전까지 등록하지 않는다.

## 4. 등록 절차

1. 출처와 이용 조건을 확인한다.
2. 원본·변경본에 안정적인 ID와 버전을 부여한다.
3. 두 이미지의 크기·크롭과 해시를 확인한다.
4. 제작자가 의도한 차이 3곳을 이름과 정규화 영역으로 등록한다.
5. PC·모바일에서 정답과 오답 경계를 육안 검수한다.
6. 서버 문제 카탈로그와 웹 자산 카탈로그를 함께 등록한다.
7. 단위·서버·브라우저 테스트를 실행한다.
8. 플레이 데이터로 난이도와 오답률을 확인한 뒤 활성화한다.

파일 순서나 업로드 순서로 original/modified를 추측하지 않는다. 카탈로그의 명시적 `originalImage`와 `modifiedImage` 필드를 사용한다.

## 5. 수량 목표

- 기능 개발과 내부 테스트: 검증된 5세트 이상
- 3분 경기: 같은 경기에서 반복되지 않는 10세트 이상
- 초기 반복 서비스: 난이도를 섞은 20~30세트 이상

## 6. 완료 조건

- 양쪽이 같은 문제 순서와 파일 버전을 사용한다.
- 현재·다음 문제를 경기 시간 손실 없이 불러온다.
- 정답이 정확히 3개이며 영역 밖 미세 변화는 판정하지 않는다.
- 모바일·데스크톱에서 같은 정규화 좌표가 같은 답이다.
- 라이선스가 확인되고 문제 버전을 재현할 수 있다.
- 신고 조사 기간 동안 이미지·정답·경기 사용 버전을 보존한다.

## 7. 새 그림 등록 (R2 + 카탈로그)

### 구조

- 이미지: R2 `puzzles/{id}/{version}/runtime/{original|modified}.webp` (1024×1024 WebP). 버전이 경로에 들어가므로 한 번 올린 주소의 내용은 바뀌지 않는다.
- 정답·제목·화풍·노출 여부: Supabase `puzzle_catalog` 행. `metadata`에 `{mode, genre, alt, original_sha256, modified_sha256}`를 둔다.
- 서버는 활성 행을 5분마다 다시 읽는다(`GET /catalog`). 실패하면 마지막 정상 목록을 계속 쓴다. 웹은 10분마다 `/catalog`를 읽고, 실패하면 번들 그림으로 진행한다.
- 대결 정답은 서버에만 있고 브라우저로 보내지 않는다. 솔로는 브라우저가 판정하므로 정답이 `/catalog`에 포함된다.
- 경기마다 활성 대결 그림 중 10점을 무작위로 뽑는다.
- R2 배포 Worker는 올라간 키라면 무엇이든 제공한다. 비활성 그림도 주소를 알면 받을 수 있으므로 공개 전 비밀이 필요한 그림은 올리지 않는다.

### 폴더 준비

그림 하나당 폴더 하나. 여러 폴더를 한 상위 폴더에 모아 두면 한 번에 처리한다.

```
inbox/
  night-market/
    original.png      # .png / .jpg / .webp
    modified.png      # 원본과 같은 크기
    puzzle.json
```

```json
{
  "id": "night-market",
  "mode": "battle",
  "title": "야시장 골목",
  "genre": "애니",
  "alt": "등불이 걸린 밤의 시장 골목",
  "difficulty": "UNRATED",
  "differences": [
    { "id": "lantern", "label": "빨간 등불", "regions": [{ "x": 0.31, "y": 0.22, "radius": 0.06 }] }
  ]
}
```

- `id`: 영문 소문자·숫자·하이픈. 수집 기록 키가 되므로 바꾸지 않는다.
- `mode`: `battle`(차이 정확히 3개, 각 영역 1개) 또는 `solo`(차이 정확히 5개, 영역 여러 개 가능).
- `genre`: 실사 / 애니 / 회화 / 카툰 / 게임.
- 좌표는 0~1 비율. 영역끼리 겹치거나 그림 밖으로 나가면 거부된다.
- 정사각형이 아니면 가운데를 잘라 1024×1024로 맞춘다(경고 표시). 잘린 뒤 좌표 기준이므로 `suggest`를 먼저 돌린다.

### 명령

```bash
pnpm puzzle suggest inbox/night-market        # 차이 자동 추천 → differences.suggested.json, preview.png
pnpm puzzle publish inbox                     # 미리 점검만 (R2·DB 변경 없음)
pnpm puzzle publish inbox --upload            # R2 업로드 + DB 등록 (아직 게임엔 안 보임)
pnpm puzzle publish inbox --upload --activate # 등록과 동시에 게임에 노출
pnpm puzzle activate night-market 2026-10-02.1
pnpm puzzle deactivate night-market
pnpm puzzle export-bundled inbox-bundled      # 기존 번들 15점을 등록용 폴더로 내보내기
```

- `suggest`는 픽셀 차이로 후보를 찾는다. 붙어 있는 두 변화는 하나로 합쳐질 수 있으니 `preview.png`를 보고 라벨과 빠진 곳을 고친 뒤 `puzzle.json`의 `differences`에 넣는다.
- 버전은 한국 날짜 기준 `YYYY-MM-DD.N`으로 자동 부여된다. 같은 그림·정답을 다시 올리면 새 버전을 만들지 않고 기존 버전을 쓴다. 정답이나 그림을 고치면 다음 번호가 된다.
- 노출을 바꾸는 명령은 트랜잭션 안에서 서버와 같은 규칙으로 전체 활성 목록을 다시 검증하고, 깨지면 되돌린다(예: 마지막 대결 그림을 내리는 경우).
- 필요한 환경변수: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_ENDPOINT`, `SUPABASE_DB_URL`. 저장소에 커밋하지 않는다.

### DB 카탈로그로 전환

1. `pnpm puzzle export-bundled inbox-bundled && pnpm puzzle publish inbox-bundled --upload --activate`로 기존 그림을 R2·DB에 올린다.
2. Worker `PUZZLE_CATALOG_SOURCE`를 `"database"`로 바꿔 배포한다(`docs/CLOUDFLARE_DEPLOYMENT.md`).
3. 이후 새 그림은 `publish --upload --activate`만으로 5분 안에 게임에 나타난다.

DB에 솔로 그림이 하나도 없으면 웹은 번들 솔로 그림 5점을 쓴다.
