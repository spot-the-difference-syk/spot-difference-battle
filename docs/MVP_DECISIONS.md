## 1. 확정한 방향

| 항목 | 결정 | 이유 |
|---|---|---|
| 핵심 대전 | 두 플레이어가 같은 원본·변경본을 동시에 비교 | 직접적인 속도 경쟁 |
| 역할 | 두 명 모두 찾는 사람 | 경기 중 제작과 관전 제거 |
| 진행 | 3개를 찾으면 상대를 기다리지 않고 다음 그림으로 이동, 경기당 한 화풍 최대 10점 | 빠른 플레이가 누적 우위가 됨 |
| 문제 공급 | 미리 제작·검수한 이미지 쌍 | 화풍·정답 품질을 경기 전에 통제 |
| 문제 순서 | 두 플레이어에게 동일한 순서 | 난이도 차이 방지 |
| 승패 | 이번 경기 그림을 먼저 끝내면 즉시 승리, 시간 종료 시 총점·오답 순 | 완주를 가장 크게 보상하고 정확도를 반영 |
| 선착 보너스 | 없음 | 앞선 플레이어의 중복 보상 방지 |
| 오답 | 1초 입력 잠금(난이도 없음) | 무작위 연타 방지, 단순한 규칙 |
| 힌트 | 온라인 경쟁전에서 제거 | 동일 조건의 관찰·속도 경쟁 |
| 시간 판정 | 서버 시각 기준 | 기기·네트워크 차이 방지 |
| 1인 모드 | 솔로 전용 그림(차이 5개)의 타임어택, 서버 판정 기록으로 그림별 주간·전체 랭킹 | 대결과 다른 난이도의 반복 플레이, 다른 사람과 기록 경쟁 |
| 플랫폼 | 웹·앱인토스·Android(WebView), 같은 웹 코드 | 한 번 만들어 여러 출구로 배포 |
| 운영 서버 | Cloudflare Worker + Durable Object, Node 서버는 개발 전용 | 상시 서버 없이 운영, 자동 배포 |
| 그림 공급 | R2 이미지 + Supabase 그림 목록, 재배포 없이 추가 | 대량 그림을 코드 수정 없이 운영 |
| 성장 | 서버가 계산하는 레벨·코인·꾸미기·수집·오늘의 목표 | 재방문 동기와 상품화 기반 |
| UI | 갤러리 콘셉트, 한국어 해요체 | 여러 화풍을 담는 중립적인 전시 분위기 |

## 2. 성공 조건

- 두 브라우저가 동일한 문제 순서로 동시에 시작한다.
- 각 플레이어가 독립적으로 문제를 완료하고 다음 문제로 이동한다.
- 제한시간 종료 시 양쪽에 같은 점수와 승패가 표시된다.
- 정답 영역과 상대의 발견 위치가 경기 종료 전에 노출되지 않는다.
- 이미지 로딩 속도가 경기 시간과 순위에 영향을 주지 않는다.
- 데스크톱과 모바일의 정규화 좌표가 같은 답으로 처리된다.
- 문제 이미지, 정답 3곳, 라이선스와 버전을 운영자가 재검토할 수 있다.

## 3. 보류 기능

- 문제별 선착순 보너스와 경쟁전 힌트
- 재대전과 결과 화면 즉시 새 매칭
- 계정, 랭킹, 시즌, 친구, 채팅, 관전과 리플레이
- 사용자 이미지 업로드
- 유료 결제와 토스 로그인(계정 연동)

## 5. 결정 근거

경기 중 이미지를 수정하면 생성 품질, 화풍 일치, 모바일 편집 난이도와 상대 대기 시간이 결과에 영향을 준다. 미리 만든 이미지 쌍을 검수하면 차이 개수와 난이도를 통제할 수 있다.

문제마다 상대를 기다리면 빠른 플레이의 보상이 약해진다. 각자 완료 즉시 다음 문제로 이동하되 같은 문제 순서를 사용한다.

문제를 먼저 완료한 플레이어는 이미 다음 문제를 먼저 시작한다. 선착 추가 점수는 같은 행동을 두 번 보상하므로 사용하지 않는다.

생성형 편집에는 의도하지 않은 미세 픽셀 변화가 생길 수 있다. 자동 픽셀 비교를 정답으로 쓰지 않고, 제작자가 의도한 정답 영역을 등록하고 사람이 검수한다. 등록 도구의 차이 추천은 초안으로만 쓴다.
