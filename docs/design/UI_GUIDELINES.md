# UI 구현 기준

> 문서 상태: CURRENT
> 기준일: 2026-10-01
> 규칙은 `../GAME_RULES.md`, 화면 요구는 `../SCREEN_SPEC.md`를 따른다.

## 디자인 시스템

- 콘셉트는 "갤러리"다. 종이색 로비(`paper-screen`)와 어두운 전시 무대, 먹색(`--ink`)과 금색(`--gold`) 포인트를 쓴다. 어떤 화풍의 그림도 돋보이도록 장식은 절제한다.
- 색·간격·컴포넌트 클래스는 `apps/web/src/styles/gallery.css`의 토큰과 클래스를 먼저 쓴다(`btn-primary`, `panel`, `glass`, `pill` 등). 같은 역할의 스타일을 새로 만들지 않는다.
- 글꼴은 저장소에 포함된 Pretendard를 쓴다. 외부 글꼴 CDN에 의존하지 않는다.
- 화면 문구는 한국어 해요체만 쓴다.
- 새 꾸미기 아이템은 `gallery.css`에 같은 ID의 스타일을 함께 만든다.

## 반응형과 입력

- 원본·수정본은 항상 같은 크기다. 세로 폰은 위아래, 가로·태블릿·PC는 좌우 배치다.
- 메뉴는 PC 상단, 폰·태블릿 하단 탭 막대다.
- 선택 좌표는 표시 크기가 아닌 정규화 좌표로 변환한다.
- 확대·이동 제스처와 정답 선택을 구분한다(6px 넘게 움직이면 드래그).
- 처리 중·입력 잠금·연결 끊김·종료 상태에서 중복 입력을 막는다.

## 포인터와 누름 반응

- PC 웹은 전용 포인터 세트(`src/assets/cursors/`)를 쓴다: 평소 금색 화살표, 누를 수 있는 곳 손가락, 수정본 보드 금색 뷰파인더, 확대한 원본은 손바닥(grab). 글자 입력칸은 I자, 비활성은 not-allowed를 유지한다.
- 이미지 포인터는 항상 기본 포인터로 대체되게 쓴다(`url(...) x y, pointer`).
- 폰·앱은 포인터가 없으므로 기본 파란 탭 표시를 끄고, 메뉴·탭·확대·아이콘·카드 버튼에 누르는 동안 살짝 작아지는 반응을 준다. 위치 이동에 `transform`을 쓰는 요소에는 적용하지 않는다.

## 접근성

- 모든 입력에 접근 가능한 이름과 명확한 포커스 표시를 제공한다.
- 정답·오답·잠금·경고를 색상만으로 전달하지 않는다.
- 아이콘 버튼에는 텍스트 이름 또는 `aria-label`을 제공한다.
- 애니메이션과 소리는 핵심 정보의 유일한 전달 수단으로 쓰지 않는다. `prefers-reduced-motion`을 존중한다.

## 컴포넌트

- 한 영역의 주요 행동은 하나를 우선 강조한다.
- 오류 원인과 복구 행동을 가까이 표시한다.
- 실제로 제공하지 않는 기능을 화면에 넣지 않는다.
- 새 의존성을 추가하기 전에 활성 앱에 필요한지 확인한다.
